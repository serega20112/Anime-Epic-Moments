# Пользовательские сценарии

## Описание

Этот документ описывает основные пользовательские сценарии, которые уже поддерживает продукт. Это самый быстрый способ понять, для чего система существует, помимо ее технической структуры.

## Как это работает

### Регистрация и вход

- Посетитель создает аккаунт с email, username и паролем.
- Пароль хешируется до сохранения.
- После успешного входа выдается cookie `access_token`.

### Поиск аниме по названию

- Пользователь открывает страницу поиска.
- Frontend вызывает `/anime/api/search`.
- Backend запрашивает внешние метаданные и возвращает нормализованный результат.

### Поиск аниме по описанию

- Пользователь описывает, какое аниме хочет найти.
- Backend может использовать LLM-assisted путь, а затем обратиться к аниме-провайдерам с фильтрами.
- Результаты можно сортировать и фильтровать по году, рейтингу и adult-параметрам.

### Добавление в избранное

- Пользователь добавляет аниме в избранное.
- Backend сохраняет внешний идентификатор и локальный snapshot карточки.
- Страница избранного рендерится из локальных данных и дополняется рекомендациями.

### Просмотр эпизода

- Пользователь открывает `/watch/<anime_id>`.
- Backend загружает или находит источники просмотра для нужного эпизода.
- Состояние плеера может сохраняться через viewing-session updates.

### Создание хайлайта

- Пользователь создает хайлайт либо через общий flow, либо прямо со страницы просмотра.
- Backend сохраняет таймкоды, спойлер, эмоцию и при необходимости watch-контекст.
- В дальнейшем хайлайты участвуют в поиске и рекомендациях.

### Генерация рекомендаций

- Система читает избранное и хайлайты.
- Жанры и текстовые сигналы превращаются в ранжированный набор кандидатов.
- Уже добавленные или использованные тайтлы исключаются.

## Почему это сделано так

- ценность продукта строится на связке сценариев, а не на наборе изолированных страниц
- избранное, хайлайты, просмотр и рекомендации усиливают друг друга
- документация по сценариям помогает оценить влияние изменений до редактирования кода
