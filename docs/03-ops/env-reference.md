# Справочник переменных окружения

## Описание

Вся конфигурация **AEM** читается из переменных окружения в момент обращения:
файла настроек с валидацией нет, каждый модуль `backend.config.sections.*`
читает своё значение через `os.getenv`.

Документ — единственная полная таблица переменных: имя, тип, значение по
умолчанию, обязательность и назначение. Значения по умолчанию приведены **как
в коде**, а не как в `.env.example`: файл-пример местами отличается (см.
[Расхождения с `.env.example`](#расхождения-с-envexample)).

## Как это работает

### Правила чтения

| Правило | Следствие |
| --- | --- |
| Флаги сравниваются с литералом `1` | `true`, `yes`, `on` и `TRUE` читаются как «выключено» |
| Числа приводятся через `int()` / `float()` | Нечисловое значение роняет чтение настройки, а не подставляет дефолт |
| Списки делятся по запятой, элементы обрезаются, пустые отбрасываются | `A,B,` и `A, B` дают одинаковый результат |
| Секреты проходят через `_clean_secret` | Значение, начинающееся с `your-`, `change-me` или `xxx`, считается отсутствующим |
| Пустая строка флага означает «выключено» | `COOKIE_DOMAIN=` — то же, что отсутствие переменной |
| Значения читаются на каждом обращении | Переменная, изменённая в процессе, подхватится без перезапуска; в контейнере это не так — там нужен рестарт |

Отсечение заглушек — защита от копирования `.env.example` без правки:
`KODIK_API_TOKEN=your-kodik-public-token` не приведёт к запросам с неверным
токеном, провайдер просто останется выключенным.

### База данных

| Переменная | Тип | По умолчанию | Обязательна | Назначение |
| --- | --- | --- | --- | --- |
| `DATABASE_URL` | строка | собирается из `POSTGRES_*` | Нет | Полная строка подключения; приоритетнее отдельных полей |
| `POSTGRES_HOST` | строка | `localhost` | Нет | Хост PostgreSQL |
| `POSTGRES_PORT` | целое | `5432` | Нет | Порт PostgreSQL |
| `POSTGRES_DB` | строка | `anime_epic_moments` | Нет | Имя базы |
| `POSTGRES_USER` | строка | `anime_epic_moments` | Нет | Пользователь базы |
| `POSTGRES_PASSWORD` | строка | `anime_epic_moments` | Нет | Пароль базы |
| `DATABASE_AUTO_INIT` | флаг | `0` | Нет | Создать схему при старте вместо миграций. В контейнере принудительно `0` |

Схема драйвера нормализуется: `postgres://`, `postgresql://` и
`postgresql+psycopg://` превращаются в `postgresql+asyncpg://`; `sqlite:///`
— в `sqlite+aiosqlite:///`. Поэтому `DATABASE_URL` в `docker-compose.yml`
задаётся без суффикса драйвера и работает.

Единственный источник схемы — Alembic. `DATABASE_AUTO_INIT=1` оставлен для
разовых локальных экспериментов и в бою приводит к базе без истории версий.

### Redis

| Переменная | Тип | По умолчанию | Обязательна | Назначение |
| --- | --- | --- | --- | --- |
| `REDIS_ENABLED` | флаг | `1` | Нет | Включает Redis как хранилище кэша и состояния безопасности |
| `REDIS_REQUIRED` | флаг | `0` | Нет | Падать при недоступности Redis вместо перехода на in-memory запасной путь |
| `REDIS_URL` | строка | `redis://localhost:6379/0` | При `REDIS_ENABLED=1` | Адрес Redis |

При `REDIS_ENABLED=0` клиент не создаётся вовсе. При `REDIS_ENABLED=1` и
`REDIS_REQUIRED=0` недоступность Redis переводит приложение на in-memory
реализации: кэш работает, но не переживает рестарт и не разделяется между
процессами.

### Безопасность и сессии

| Переменная | Тип | По умолчанию | Обязательна | Назначение |
| --- | --- | --- | --- | --- |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | целое | `30` | Нет | Срок жизни access-токена |
| `REFRESH_TOKEN_EXPIRE_DAYS` | целое | `30` | Нет | Срок жизни refresh-токена |
| `COOKIE_SECURE` | флаг | `0` | Нет | Флаг `Secure` у cookie; при `1` включается HSTS |
| `COOKIE_SAMESITE` | строка | `Lax` | Нет | Политика `SameSite` |
| `COOKIE_DOMAIN` | строка | пусто | Нет | Домен cookie; пусто — домен текущего хоста |
| `CSRF_TOKEN_NAME` | строка | `csrf_token` | Нет | Имя поля и cookie CSRF-токена |
| `HSTS_MAX_AGE` | целое | `63072000` | Нет | `max-age` заголовка HSTS, два года |
| `TRUSTED_PROXIES` | список | пусто | Нет | IP и CIDR прокси, которым доверяется `X-Forwarded-For` |

`TRUSTED_PROXIES` пуст по умолчанию намеренно: при пустом списке
`X-Forwarded-For` игнорируется всегда, и клиент не может подделать свой адрес,
влияя на ограничители частоты. Заполнять список нужно только тогда, когда AEM
стоит за известным обратным прокси.

В продакшене обязательны `COOKIE_SECURE=1`, HTTPS в `APP_PUBLIC_SCHEME` и
заполненный `APP_ALLOWED_ORIGINS`: без них cookie уходит без `Secure`, а HSTS
не отдаётся.

Лимиты маршрутов каталога, поиска и реакций заданы в коде маршрутов, а не в
окружении: там они привязаны к конкретной ручке и меняются вместе с ней.

Срок блокировки входа читается из `ACCOUNT_LOCK_DURATION_SECONDS`: провайдер DI
передаёт значение в `AccountLockService`, а константа `LOCK_DURATION_SECONDS = 1800`
в `account_lock_service.py` остаётся только значением по умолчанию. Меняется на
работающем окружении перезапуском приложения: уже выставленные блокировки доживают
свой старый TTL, новые получат новый срок.

### Вход через Google

| Переменная | Тип | По умолчанию | Обязательна | Назначение |
| --- | --- | --- | --- | --- |
| `GOOGLE_CLIENT_ID` | строка | пусто | Нет | OAuth Client ID мобильного клиента; без него вход через Google отклоняет любой токен |
| `GOOGLE_TOKENINFO_URL` | строка | `https://oauth2.googleapis.com/tokeninfo` | Нет | Адрес проверки подлинности ID-токена Google |

`GOOGLE_CLIENT_ID` сверяется с полем `aud` ID-токена: несовпадение означает,
что токен выписан не для этого клиента, и вход отклоняется. Пустое значение
намеренно выключает вход через Google, а не открывает его для любых токенов.
Эти переменные относятся к аутентификации и не пересекаются с `GOOGLE_API_KEY`
из группы каталога и LLM, несмотря на общий префикс.

этом остаётся рабочей, но пользователь не получит код.

### Расхождения с `.env.example`

Файл-пример удобнее для старта, поэтому несколько флагов в нём выставлены

| Переменная | В коде | В `.env.example` | Практическое следствие |
| --- | --- | --- | --- |
| `APP_DEBUG` | `0` | `1` | Пример запускается в отладочном режиме, где `SECRET_KEY` необязателен |
| `KINOBOX_ENABLED` | `1` | `0` | Пример выключает агрегатор, включённый по умолчанию |
| `ANIMEGO_ENABLED` | `1` | `0` | Пример выключает скрапер, включённый по умолчанию |
| `SIBNET_ENABLED` | `1` | `0` | Пример выключает экстрактор, включённый по умолчанию |
| `POSTGRES_DB` и др. | `anime_epic_moments` | `anime_epic_moments_db` | Значения в `.env` перекрывают дефолты, конфликта нет |

## Почему это сделано так

- Переменные читаются функциями по месту, без единого класса настроек: модуль
  конфигурации — единственный, что знает про `os.getenv`, а остальной код
  получает уже готовые значения через DI.
- Литерал `1` вместо `true` — простая и однозначная проверка: `os.getenv(...)
  == "1"` невозможно прочитать двояко, в отличие от `bool("false")`.
- Отсечение заглушек защищает от самой частой ошибки развёртывания —
  скопированного `.env.example` без правки секретов.
- Пустой `TRUSTED_PROXIES` по умолчанию: доверять заголовку `X-Forwarded-For`
  без явной настройки означало бы позволить клиенту подделать свой IP.
- Нормализация схемы `DATABASE_URL` нужна, чтобы одинаково принимать строки
  из `docker-compose`, из облачных панелей и из локального `.env`.
- Отдельные `POSTGRES_*` и `DATABASE_URL` — компромисс: compose удобнее
  собирать из частей, а внешние панели дают готовую строку.

## Где в коде

- `src/backend/config/sections/server.py` — приложение, журнал, тело запроса, CORS
- `src/backend/config/sections/database.py` — URL базы и нормализация схемы
- `src/backend/config/sections/redis_.py` — Redis
- `src/backend/config/sections/security.py` — `SECRET_KEY`, cookie, токены, HSTS, доверенные прокси
- `src/backend/config/sections/auth.py` — сроки почты и лимиты аутентификации
- `src/backend/config/sections/validation.py` — лимиты строк и выборки
- `src/backend/config/sections/features.py` — фиче-флаги
- `src/backend/config/sections/external/` — каталог, LLM, провайдеры, поддержка, медиа-прокси
- `.env.example` — пример конфигурации с комментариями
- `docker-compose.yml` — переменные контейнеров
- `scripts/entrypoint.sh` — вывод `APP_BASE_URL` и `APP_ALLOWED_ORIGINS` из `APP_PUBLIC_*`
