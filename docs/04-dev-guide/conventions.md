# Соглашения кодовой базы

## Описание

Документ описывает обязательные правила кода **AEM**: чем проверяется стиль,
как пишутся докстринги и комментарии, как кодировать имена, типизацию, ошибки,
логирование и транзакции, и в каком формате делать коммиты.

Правила разбиты на два класса:

- **автоматические** — их держат гейты (`ruff`, `scripts/check_style.py`,
  `import-linter`), нарушение блокирует коммит или CI;
- **ревьюшные** — машинно невыразимые (размер коммита, состав изменений),
  проверяются глазами по чек-листу.

| Область | Правило | Проверяет |
| --- | --- | --- |
| Формат и статика | `ruff.toml` | `uv run ruff check`, `uv run ruff format` |
| Докстринги и комментарии | русский Google-style, запрет `#` | `uv run python scripts/check_style.py` |
| Направления импортов | четыре слоя, DIP | `uv run python scripts/check_imports.py` |
| Типизация | аннотации в публичных сигнатурах | ревью (мейкера нет намеренно) |
| Ошибки | `DomainError` и `UseCaseResult` | ревью |
| Логи | именованный логгер, маскирование секретов | ревью |
| Коммиты | Conventional Commits | ревью |

## Инструменты стиля

Конфигурация живёт в `ruff.toml` (не в `pyproject.toml`), потому что ruff
используется и как линтер, и как форматтер, и как `isort`, а независимый файл
читается при правке правил быстрее.

| Хук pre-commit | Команда | Что делает |
| --- | --- | --- |
| `ruff-check` | `uv run ruff check src tests --fix` | статика и автофиксы |
| `ruff-format` | `uv run ruff format src tests` | единый формат |
| `lint-imports` | import-linter через `python -c` с добавлением `src` в путь импорта | контракты слоёв |
| `pytest-unit` | `uv run pytest tests/unit -q --no-cov` | быстрые тесты до коммита |

Все четыре хука объявлены как `repo: local` с `language: system`, поэтому
вызывают `uv` из окружения разработчика и не создают отдельное виртуальное
окружение для pre-commit. `pass_filenames: false` означает, что проверка идёт по
всему каталогу, а не только по изменённым файлам: пропущенный `#`-комментарий в
соседнем модуле не пропустят, даже если собственный дифф чист. Первые два хука
срабатывают на Python-файлы, остальные — на любой коммит.

`--no-cov` в последнем хуке обязателен: порог `fail_under` относится к общему
покрытию, а не к его части, и без него локальный коммит падал бы на пустом
месте. Хуки не затрагивают `scripts/` и `migrations/` — их проверяет CI
полным `uv run ruff check src tests migrations`. Тот же контроль импортов, что
в хуке, доступен вручную командой `uv run python scripts/check_imports.py`.

### Правила ruff

Выбранные группы (`select`):

| Код | Группа | Зачем в AEM |
| --- | --- | --- |
| `E`, `W` | pycodestyle | базовая разборность форматирования |
| `F` | pyflakes | мёртвые импорты, несуществующие имена |
| `I` | isort | порядок импортов, иначе диффы шумят |
| `N` | pep8-naming | имена классов и функций по PEP8 |
| `D` | pydocstyle | форма докстрингов, см. ниже |
| `UP` | pyupgrade | синтаксис не старше `target-version` |
| `ERA` | erased-comment | закомментированный код запрещён |

Отключённые (`ignore`) и почему:

| Код | Причина |
| --- | --- |
| `D100`–`D104`, `D107` | требовать докстринг у каждого публичного объекта — шум на всём объёме кода; наличие и язык докстринга проверяет `check_style.py`, который строже |
| `D203`, `D212`, `D213` | конфликтуют между собой по позиции первой строки многострочного докстринга |
| `D401` | императивное написание первой строки не применимо к русским докстрингам |
| `D413`, `D415` | пустая строка после секции и точка в первой строке — несущественно |
| `E501` | длина строки контролируется `ruff format` (`line-length = 100`); жёсткий лимит для докстрингов с кириллицой резал бы слова |

`per-file-ignores`: `__init__.py` разрешает неиспользуемые импорты (`F401`) —
это фасады реэкспорта; в `tests/**` отключены правила докстрингов (`D`).

### Правила check_style.py

Скрипт проверяет `src/backend` по двум правилам, которые ruff не выражает.

| Правило | Формулировка | Исключения |
| --- | --- | --- |
| `COMMENT` | в коде `src/backend` нет `#`-комментариев | директивы инструментов: `noqa`, `type:`, `fmt:`, `ruff:`, `isort:`, `pragma:` |
| `DOCSTRING` | у каждого модуля, класса, функции и метода есть докстринг с кириллицей | приватные функции из одного оператора; имена `__init__`, `__repr__`, `__str__`; декораторы `overload`, `property`, `setter`, `deleter`, `cached_property` |

Комментарий-объяснение переносится в докстринг: токен-разбор (`tokenize`)
гарантирует, что решётка внутри строкового литерала — URL или пример команды —
нарушением не считается.

## Как писать код

### Докстринг

Формат — Google-style, язык — русский, первая строка — что это, затем `Args`,
`Returns`, `Raises` с именами параметров.

```python
async def execute(self, command: AddMomentNoteCommand) -> MomentNote:
    """Создать заметку и зафиксировать транзакцию.

    Args:
        command: Данные заметки.

    Returns:
        MomentNote: Сохранённая заметка.

    Raises:
        ValidationError: Если текст пуст или превышает предел.
    """
```

Пишутся `Raises` только для исключений, которые метод бросает сам; проброс
чужого исключения в `Raises` не перечисляется.

### Типизация

| Правило | Формулировка |
| --- | --- |
| Аннотации | обязательны в сигнатурах публичных функций, методов, портов и DTO |
| Синтаксис | `X \| None` вместо `Optional[X]`, `list[str]` и `dict[str, int]` вместо `typing.List` |
| Отложенные импорты | `from __future__ import annotations` в модулях с циклическими или тяжёлыми аннотациями |
| Изменчивость | DTO и value objects — `@dataclass(frozen=True, slots=True)` |
| Порты | `ABC` с `@abstractmethod` для репозиториев и сервисов; `typing.Protocol` — только когда нужна структурная типизация без наследования |
| Разбор ответов | `isinstance` и `match` по dataclass, а не `dict`-ключи с `.get()` |

Mypy в CI нет намеренно: строгой типизации весь код `src/backend` не
выдерживает, а частичная дала бы ложное чувство гарантии. Аннотации нужны для
читаемости сигнатур и подсказок IDE, их проверяет ревью.

### Имена

| Роль | Шаблон | Пример |
| --- | --- | --- |
| Сущность домена | `domain/entities/<feature>/<name>.py` → класс `<Name>` | `domain/entities/favorite/favorite.py` → `Favorite` |
| Порт репозитория | `<Aggregate>Repository(ABC)` | `application/interface/repositories/favorite_repository.py` |
| Адаптер репозитория | тот же класс `<Aggregate>Repository`, пакет `repositories/<aggregate>_repository/` | `repositories/favorite_repository/favorites.py` |
| Технический порт | `<Name>Interface(ABC)` (реже `<Name>Port`) | `UnitOfWorkInterface`, `LLMClientInterface`, `ImageStoragePort` |
| Сценарий | `<Verb><Noun>UseCase` с методом `execute` | `AddFavoriteUseCase` |
| DTO | `<Verb><Noun>Command` / `<...>Query` / `<...>Result` | `AddFavoriteCommand` |
| Схема HTTP | `<Verb><Noun>Request` / `<...>Response` | `AddMomentNoteRequest` |
| Маршрут | `presentation/api/v1/<feature>_route.py`, переменная `<feature>_router` | `favorite_route.py` → `favorite_router` |
| Провайдер DI | `infrastructure/di/providers/<feature>.py` | `providers/favorite.py` |

Два правила об именовании, которые регулярно ломают на ревью:

- порт и его адаптер могут называться одинаково, потому что различаются модулем
  и слоем; повтор имени — не коллизия, а указание на одну и ту же роль;
- сокращающий алиас порта запрещён: `AnimeApiClientInterface as AnimeApiClient`
  нельзя, порт импортируется под своим именем. Алиас оправдан только тогда, когда
  каноническое имя в модуле уже занято: `FavoriteRepository as
  FavoriteRepositoryPort` в `unit_of_work.py` (там же живёт адаптер с именем
  `FavoriteRepository`), `ExternalServiceError as DomainExternalServiceError`
  в `external/_common/errors.py`, `import html as html_mod` в скраперах. Алиас
  класса порта ломает `isinstance` в двойниках и подсказки IDE: в месте объявления
  тип выглядит как конкретный клиент, а не как абстракция.

### Обработка ошибок

Иерархия доменных ошибок — в `domain/exceptions.py`:

| Исключение | Когда бросается | HTTP-код наружу |
| --- | --- | --- |
| `ValidationError` | нарушен инвариант сущности | 400 |
| `InvalidEmailError`, `InvalidUsernameError` | неверный email или имя пользователя (подклассы `ValidationError`) | 400 |
| `NotFoundError` | сущности нет по идентификатору | 404 |
| `DuplicateError` | нарушен уникальный контекст | 409 |
| `AuthenticationError` | креды не подходят | 401 |
| `AuthorizationError` | прав на действие нет | 403 |
| `InvalidTokenError` | токен просрочен или подделан | 401 |
| `ExternalServiceError` | отказала внешняя система | 502 или деградация |

Вне этой иерархии домен ошибок не бросает: `ValueError` из правила сущности
представление не различит от `ValueError` из разбора чужих данных.

Выбор между исключением и результатом:

- `UseCaseResult` (флаг `ok`, HTTP-код, данные или код ошибки; конструкторы
  `success` и `failure`) — когда вызывающая сторона обязана различать причины
  отказа и не может обработать `raise` (например, разные коды ответов в одном
  сценарии);
- доменное исключение — когда вариантов «сделай или упади» достаточно, и
  обработчик ошибки один (middleware или `try` в маршруте).

Коды HTTP берутся из констант, а не из литералов: `starlette.status` в
`UseCaseResult` и в прикладном слое, `http.HTTPStatus` в представлении и в
ответах инфраструктуры. Числа `403`, `303`, `502` в коде запрещены — границы
диапазонов тоже выводятся из констант (`HTTP_400_BAD_REQUEST`,
`HTTP_300_MULTIPLE_CHOICES`). Детали — в
[слоях и правилах](../01-architecture/layers-and-rules.md).

Широкий `except Exception` допустим только на границе с внешним миром — HTTP-
клиенты, LLM, Redis и база, прокси, парсинг чужих манифестов — и обязан
логировать контекст и объяснять себя в докстринге: читающий код должен видеть,
почему отказ считается штатной деградацией, а не спрятанным багом. В остальном
ловится конкретный тип.

### Транзакции и репозитории

| Правило | Почему |
| --- | --- |
| `commit()` — только в `SqlAlchemyUnitOfWork` | граница транзакции принадлежит сценарию, а не адаптеру |
| `flush()` — внутри репозитория | нужны сгенерированные идентификаторы и проверка unique до коммита |
| один сценарий — один блок `async with self._uow` | вложенные блоки открыли бы вторую транзакцию на той же сессии |
| сброс кэшей и внешние вызовы — после блока `async with` | иначе кэш очистится до фиксации и вернёт устаревшие данные |
| запросы — через ORM-выражения, `text()` только с параметрами | конкатенация строк в SQL запрещена |
| адаптер регистрируется в `_REPOSITORY_TYPES` | без строки `uow.repository(Port)` бросит `LookupError` |

### Логирование

| Правило | Формулировка |
| --- | --- |
| Логгер | `logging.getLogger("anime_epic_moments")` — именованный, а не модульный, чтобы уровень и обработчики задавались корнем один раз |
| Сообщения | стиль `ключ=значение`: `logger.info("smart_search_degraded provider=%s", name)` — без предложений и без пунктуации |
| Секреты | запрещены в сообщениях; `SecretMaskFilter` маскирует `token=`, `Bearer`, адреса почты, но полагаться на него как на sanitizer нельзя |
| Аудит | бизнес- и security-события — через `log_business_event` и `log_security_event`, они пишутся в отдельный логгер `security.audit` |
| Формат | `LOG_FORMAT=json` в проде, `text` локально; время всегда UTC с суффиксом `Z` |
| Шум | `httpx`, `httpcore`, `urllib3`, `websockets`, `asyncio` приглушены до `WARNING`; `uvicorn.access` и `gunicorn.access` отключены — access пишет middleware |
| `print` | запрещён: вывод в stdout мимо форматтера ломает структуру логов и не маскирует секреты |

### Конфигурация

Новая переменная окружения добавляется в `config/sections/<область>.py` как
функция с дефолтом и попадает в `Settings`. Прямые `os.getenv` вне `config/`
запрещены; единственное исключение — `utils/logging.py`, который читает
`LOG_FORMAT` до создания настроек, потому что форматтеры нужны для самого
процесса инициализации.

После добавления переменной обязателен пункт в
[справочнике окружения](../03-ops/env-reference.md).

### Зависимости

| Правило | Команда |
| --- | --- |
| Новая зависимость | `uv add <пакет>` — обновляет и `pyproject.toml`, и `uv.lock` |
| Инструмент для разработки | `uv add --dev <пакет>` |
| Инструмент проверки границ | `uv add --group lint <пакет>` |
| Перебор lock-файла | `uv lock` |
| Обновление версий | `uv lock --upgrade` |

`uv.lock` вручную не правится и не создаётся через `pip freeze`: единственный
источник истины — `pyproject.toml`, а lock — его машинная производная.
`pip`, `requirements*.txt` и отдельный `venv` в проекте не используются.

### Что не попадает в коммит

- `.env` и любые реальные секреты: в `.env.example` остаются только заглушки;
- артефакты инструментов — `__pycache__`, `.ruff_cache`, `.import_linter_cache`,
  `.coverage`, `.venv`, `node_modules`;
- одноразовые скрипты и локальные выгрузки данных;
- бинарные файлы больше нескольких мегабайт;
- перегенерированный `docs/api/openapi.json` без изменения маршрутов (и наоборот:
  изменение маршрута без пересборки артефакта).

## Коммиты и pull request

### Формат сообщения

Conventional Commits в упрощённом виде: `<type>: <description>`.

| Тип | Назначение |
| --- | --- |
| `feat` | новая функциональность |
| `fix` | исправление дефекта |
| `refactor` | изменение кода без смены поведения |
| `docs` | документация |
| `test` | тесты |
| `chore` | зависимости, конфигурация инструментов, сборка |
| `ci` | пайплайны и Workflow-файлы |
| `update` | обновление данных, справочников, артефактов |

Правила строки:

- тип и двоеточие — на английском, описание — на русском, со строчной буквы,
  без точки в конце;
- Breaking change — `!` после типа (`feat!: перевести сессии на refresh-токены`)
  и абзац-пояснение в теле коммита;
- один коммит — одна логическая единица: фича, фикс или чистка формата.
  Правки `ruff format` выносятся в отдельный `chore:`-коммит, иначе ревью
  тонет в шуме форматирования.

| Хорошо | Плохо |
| --- | --- |
| `feat: добавить лимит хайлайтов для гостей` | `refactoring` (непонятно, что изменилось) |
| `fix: не закрывать транзакцию при ошибке прокси` | `fixes` |
| `chore: поднять fastapi до 0.116.1` | `[AEM-async-version] add and fix: refactoring and adding new providers` |
| `docs: описать скоупы Dishka` | `update files` |

Изменение зависимостей коммитится вместе с `uv.lock`: закоммитить отдельно
`pyproject.toml` значит сломать `uv sync --frozen` в сборке образа.

### Ветки и pull request

| Правило | Формулировка |
| --- | --- |
| Имя ветки | `feature/<краткое-имя>`, `fix/<имя>`, `chore/<имя>`, `docs/<имя>` |
| Размер PR | ориентир — до 400 изменённых строк и до 15 файлов; больше — делить |
| История | линейная: rebase или squash вместо merge-коммитов, кроме давно живущих веток |
| Описание PR | что и зачем, какие гейты прогнаны, какая документация обновлена |
| Документация | обновляется в том же PR, что и код: фича без правки документа-владельца не мержится |

Что должно быть в PR с новой фичей: код, тесты (уровень и способ задавать
данные определяет [05-testing](../05-testing/01-testing-strategy.md)),
обновлённые артефакты
(`docs/api/openapi.json`, матрица маршрутов), правки документов-владельцев
фактов, при необходимости — запись в [06-adr](../06-adr/).

### Чек-лист ревью

| Блок | Что смотрят |
| --- | --- |
| Слои | направление импортов, отсутствие SQL и HTTP в `application`, сущности без ORM |
| Границы | проверка владельца ресурса, `require_self`, коды ответов в `responses` |
| Ошибки | конкретные `except`, корректный выбор «исключение или `UseCaseResult`» |
| Данные | `commit` только в UoW, индексы в новой миграции, обратимость ревизии |
| Производительность | N+1 в репозиториях, кэшируемые вызовы, таймауты внешних клиентов |
| Стиль | докстринги, именованный логгер, отсутствие `#`-комментариев и `print` |
| Документация | обновлён документ-владелец факта, артефакты пересобраны |

## Гейты перед коммитом

```bash
uv run ruff check src tests migrations
uv run ruff format src tests migrations
uv run python scripts/check_style.py
uv run python scripts/check_imports.py
uv run pytest
```

CI прогоняет тот же набор и ещё три проверки: синхронность `uv.lock` с
`pyproject.toml` (`uv lock --check`), актуальность артефакта OpenAPI
(`uv run python scripts/export_openapi.py --check`) и цикл миграций на чистом
PostgreSQL — `upgrade head`, `check`, `downgrade base`, снова `upgrade head`.

Триггеры пайплайна — push и pull request в `main` или `master`. Ветки
`feature/*` и `fix/*` гейтов в CI не имеют, поэтому локальный набор выше обязателен
перед push: зелёный CI после мержа не спасёт уже сломанное имя переменной.

### Механические гарантии помимо линтеров

Часть правил, которые трудно выразить правилом ruff, проверяется разбором
синтаксического дерева и сравнением артефактов:

| Что гарантируется | Как |
| --- | --- |
| Сценарий вызывается из представления по шаблону: `await use_case.execute(<Command \| Query>)` | AST-обход `src/backend/presentation` ловит `execute` с примитивами или только с именованными аргументами |
| `await` стоит только над корутиной | AST-обход всего `src/backend`: имя функции сверяется с её объявлением по проекту |
| DI-граф полон и согласован с фасадом сценариев | резолв каждого `*UseCase` в `Scope.REQUEST` и сверка аннотаций `@provide` с `__all__` фасада |
| Контракт JSON API не разошёлся с кодом | пересборка OpenAPI-схемы и побайтовое сравнение с `docs/api/openapi.json` |
| Матрица маршрутов соответствует коду | генератор `scripts/export_route_matrix.py` пересобирает механические колонки |
| Границы слоёв не нарушены | контракты import-linter, включая два согласованных исключения |

Эти проверки существуют как код в репозитории; стандарт написания самих тестов
определён в разделе [05-testing](../05-testing/01-testing-strategy.md).

## Почему это сделано так

Стандарт докстрингов строже, чем ruff, потому что `D100`–`D104` отключены:
требовать докстринг у каждого публичного объекта машинно — значит получить
формальные строки «Get the user». Вместо этого наличие и язык докстринга
проверяет `check_style.py`, который работает по AST и не даёт сдать пустую
строку или английский текст.

Запрет `#`-комментариев — не пуризм. Комментарий стареет молча: его никто не
обязан обновлять при правке кода, а докстринг видит и IDE, и генератор
документации, и ревью. Директивы инструментов разрешены, потому что они
управляют поведением проверщика, а не описывают намерение.

Строгий режим типов (Mypy) не включён осознанно. Типизация в AEM —
договорённость о сигнатурах, а не гарантия: проверка `dict`-ответов внешних
провайдеров от аннотаций не улучшается, а время на приведение всего кода к
строгому режиму окупируется ревью и тестами.

Порог покрытия `fail_under = 82` выставлен на единицу ниже фактического замера,
чтобы он ловил молчаливое проседание и оставлял запас правкам, которые временно
уменьшают число строк.

Конвенциональные коммиты взяты в упрощённой форме без issue-ссылок и скоупов:
проект ведёт один-два разработчика, и сложный формат деградирует в мусор быстрее,
чем успевает помочь.

## Где в коде

- `ruff.toml` — правила линтера и форматтера
- `scripts/check_style.py` — проверка докстрингов и комментариев
- `pyproject.toml` — pytest, import-linter, порог покрытия
- `.pre-commit-config.yaml` — четыре хука
- `.github/workflows/ci.yml` — состав гейтов в CI
- `src/backend/domain/exceptions.py` — иерархия доменных ошибок
- `src/backend/application/use_cases/result.py` — `UseCaseResult`
- `src/backend/utils/logging.py` — логгер, маскирование секретов, аудит
- `src/backend/infrastructure/database/unit_of_work.py` — граница транзакции
